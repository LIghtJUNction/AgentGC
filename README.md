# AgentGC

追踪 AI Agent 创建和修改的文件，让持续运行的 Agent 留下的产物可查、可管、可清理。

## 为什么做

Agent 持续运行时，会不断生成文件、修改内容、留下临时产物。时间一长，文件来源和用途难以辨认，CPU、内存和磁盘占用也可能持续增长。

AgentGC 希望先把这些文件的来源与变化记录清楚，再帮助用户整理产物、识别需要保留的内容，以及定位可以清理的残留。

## 产品形态

**Skills + CLI**：Skills 面向 Agent 的工作流程，CLI 面向用户的查询与管理操作。

## 核心能力

- **主动跟踪**：记录 Agent 创建和修改的所有文件，以及相关来源和变化。
- **排序**：按时间、大小、活跃程度等维度整理文件。
- **搜索**：快速查找 Agent 产物及其变更记录。
- **标记**：区分重要产物、临时文件、待确认内容与可清理残留。
- **索引**：建立可检索的文件目录，保留文件与 Agent 活动之间的关联。

## 边界与原则

- 优先解决文件追踪与管理问题，不承诺仅靠文件管理就解决所有 CPU 和内存占用问题。
- 文件被 Agent 创建或修改，不代表它可以被删除。
- 清理前应明确文件来源、用途和当前引用，保护正在使用的文件与必要恢复材料。
- 工具自身的追踪与索引应保持轻量，避免成为新的资源负担。

## 当前状态

项目初始化阶段，仅记录产品定位、核心能力与边界。暂不确定技术选型，不包含 CLI 或 Skills 的实现。
